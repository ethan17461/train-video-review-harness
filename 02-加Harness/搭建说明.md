# 加 Harness 版 · 搭建说明

## 一、文件夹里有什么，各对应哪个决定

| 文件 | 是什么 | 对应决定 |
|---|---|---|
| `数据/作品清单.csv`、`数据/播放快照.csv` | 和基线测试完全相同的两张表（文件指纹一致） | 对照实验：数据不变 |
| `数据/复盘设置.json` | 统计截止时间、达标线 1000、最少样本数 10。由负责人设定 | 决定 2、4 |
| `工具/review-periods.mjs` | 计算核心，沿用 Codex v2，没改 | — |
| `工具/review-tools.mjs` | 把计算结果整理给 AI、按组数条数、检查报告数字、保存报告 | 决定 1、4、5、6 |
| `工具/mcp-server.mjs` | 把上面的功能做成 4 个工具，接进 DeepSeek Harness | — |
| `工具/tools.test.mjs` | 17 项自动测试 | 验证 |
| `.agents/skills/video-review/SKILL.md` | 给 AI 看的规则说明书 | 决定 1–5 的规则部分 |
| `AGENTS.md` | 一句话：复盘前先加载 video-review | 保证规则被读到 |
| `cordis.patch.yml` | DeepSeek Harness 的配置：用什么模型、给什么能力、接哪些工具 | 决定 6 |
| `复盘输出/` | AI 唯一能写的地方 | 决定 6 |

桌面上的「启动 DeepSeek Harness（加Harness版）.command」用这份配置启动。原版启动文件没动。

## 二、4 个工具

| 工具                   | 做什么                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------- |
| `get_review_summary` | 读复盘结果。冲突的数据不给数字，只标「冲突-需人工核查」和行号（决定 1）。每条没达线的作品给出「离达标线还差多少」（决定 2 允许陈述的事实）。缺统计截止时间时直接停止 |
| `get_work_evidence`  | 查某条作品的来源行号                                                                            |
| `compare_groups`     | 按平台或标题分组数条数。少于 10 条时提醒「只能写进待验证假设」（决定 4）                                               |
| `save_report`        | 保存报告的唯一出口。先检查数字，通过才存进「复盘输出」；不通过退回改一次；第二次仍不通过，存成「待人工核查」版本（决定 5、6）。统计表由代码自动附上，AI 只写解读   |

## 三、检查点怎么查数字（决定 5）

规则只有一条：报告里提到某条作品的数字，必须是工具给过的数字（播放量、离达标线还差、7 天比 24 小时多）。

- 它会看句子里说的是 24 小时还是 7 天，再对这条作品的数据。
- 拿基线报告试：第 69 行「W02、W06 都正好 1000」被抓到，W04 按 400 算的几处也被抓到。
- 写对的报告不会被误判（有测试）。

## 四、和 Codex 版相比，我做的改动（需要你确认）

1. **权限的关法换了。**Codex 的写法是列一张「关掉」清单。我查了网页版的配置，发现那些能力藏在 Agent 预设里，按 Codex 的写法关不掉（运行命令、读写文件仍然开着）。所以改成新建一个预设 video-review，只列需要的东西，没列的就没有。
2. **只加载这一个技能。**原版会把你电脑里另外约 60 个技能都列给它。改成只读本文件夹的 video-review。连通测试里，同一个问题的消耗从 14.3K 降到 2.8K。
3. **去掉了 Codex 的「播放目标完成度」评分。**这是 Codex 自己加的，作业和你的决定都没要求。
4. **去掉了 Codex 的 `check_policy` 关键词检查工具。**它靠关键词判断请求是否越线，漏判很容易。现在危险的能力已经不给了，这个工具就多余了。
5. **冲突的数值在查来源时也不给。**Codex 版在 `get_work_evidence` 里会把 300 和 400 都返回，AI 还是能挑。按你的决定 1，改成只给行号。
6. **达标线和截止时间放进设置文件。**AI 没有读写文件的能力，所以改不了它们。决定 2 除了规则，又多了一层权限保护。

## 五、已经验证的

- 17 项自动测试全部通过：汇总条数和正确答案一致（24 小时有效 4 条、达线 1 条；7 天有效 4 条、达线 3 条），冲突不给数字，样本提醒，检查点抓错，不误判，改一次仍不对转人工，缺截止时间停止，工具服务能启动。
- 在 DeepSeek Harness 网页版里做了 3 次连通测试：它只能看到 4 个复盘工具和 1 个加载规则的工具，技能只有 video-review，调用工具能拿到正确结果。这 3 个测试会话留在「02-加Harness」工作区里，名字带「连通性测试」，可以忽略。

## 六、已知局限

- 检查点只查「作品编号旁边的数字」。没提作品编号的数字、用中文写的数字（比如「三条」）查不到。
- 第二次不通过才转人工，这个计数在工具服务重启后清零。
- 表格里如果有带逗号的标题，读表会出错（这次的数据没有）。
- 规则说明书里的规则（决定 2、3、4 的一部分）代码管不住，要靠三次测试看它守不守。
- 检查点只查存进「复盘输出」的报告。AI 在对话里直接回复的文字不经过检查。
- 第一次测试发现：检查点把「分组里的条数」当成总数误判，AI 为了通过检查把对的改成了错的。已修复，补了 2 项测试（共 11 项）。修复后需要重启加 Harness 版才生效。
- 第一次重跑又发现两处误判：「不按 0 算」里的 0、「分别」按顺序对应的写法。已修复，再补 2 项测试（共 13 项）。
- 权限已放开（2026-11-18，负责人决定）：Agent 现在可以运行命令、读写文件和搜索文件，所以第一节和第四节里「AI 没有读写文件的能力」的说法不再成立。不读原始表、不改设置、报告必须过检查，这几条现在靠规则。放开前的配置在 `cordis.patch.最小权限版.yml`。
- 不迎合检查（2026-11-18 加入）：AI 确认没写错时，可以保持原文，并在 `save_report` 的 `dispute_note` 里写明争议，报告会存成「待人工核查」版本。被退回后才通过的报告，末尾会留下「检查记录」。代码判断不了 AI 是不是在迎合，所以这一条仍要靠规则和人工查看。这部分已通过自动测试（共 17 项），还没有在 DeepSeek Harness 里实跑。
